# Recorded-evidence typed-claims contract vectors

These are authored synthetic fixtures for the [exact profile](../recorded-v0.1.md),
not captured incident events, authenticated sources, accepted history or an implemented
native evidence reader. `example.json` contains five documentary witnesses of four
local asserted identities, with one equal redelivery, explicit asserted order and
an unresolved outside boundary. Unknown/tied reported time is not an ordering rule.

`expected-report.json` and `expected-claim-digests.json` are mathematical contract
after-states, not observations of future APIs. Context/empty/clock-ID-renamed and
clock-origin-changed positives distinguish exact documentary identity and resolved
basis binding. Type/pin/identity/original-integrity/reference/order/profile/authority
negatives refuse at their own layers. Size/depth/work cases are generated in tests
rather than embedding oversized data here. No standalone schema proves full admission.

`resource-inputs.json` is an explicit repository build/test input list, not an artifact
URI resolver. Read those approved exact bytes to construct the contiguous blob for
`registry.json`; the header itself has no paths or fetch permissions. It includes
the profile, exact semantics/cores1–12 and the small MPL-2.0 named-type resource.
All source/instance/definition/clock/receipt identities are fictional assertions.

The existing native Resources/type_descriptor/literal APIs check five worked payloads
and reject two malformed/unsupported payload/type cases. That baseline establishes
only current literal/type behavior. The test-only structural/vector checker is not
the future Rust artifact reader, host authentication, actual chronology or execution.
