# Experimental paired prototype contract vectors

These are finite authored expectations for the [experimental mapping](../paired-prototype-v0.1.md),
not an implementation, visual standard, browser/user study or authorization evidence.
The original source19 example is extended with a real unused pinned number-type
resource. Existing PR #110 native APIs actually admit/lower/import it and produce
its exact source/companion/authoring/semantic binding. Existing native Candidate
spans supply declaration locations. The proposed view's entity rows/default placement
are finite authored contract data; no proposed view/bridge/UI code produced them.

The 21 entities include source-only types/protection/test/input and a resource that
has only a companion location. Symbol spans explicitly locate their owners. The
complete IR, source and opaque notes remain preserved; unused source-only structure
is not reconstructed from IR. The semantic revision remains the original example's.

`registry.json` frames the exact existing MPL-2.0
[number-type bytes](../examples/service.named-types.json); the manifest records their
path/digest without relicensing or copying them. Positive catalog/error examples
illustrate protocol structure, not real sessions/permissions. Negative view vectors
exercise completeness, genuine location provenance, unknown kinds and stale binding;
registry vectors exercise ranges and forbidden authority fields. Schemas alone
cannot check all consistency/permission invariants.

`vectors.json` raw-pins schemas and every worked artifact. Acceptance/pinning in
ADR-0096 precedes production implementation. Real native/Wasm/browser actions,
complete construct coverage, trusted access enforcement and actual representative
users remain future evidence; generated expectations cannot substitute for them.
