# ADR-0065: Adopt demonstrated RP-01 capture before further generalization

**Status:** Accepted under Project Owner delegation; effective on parent/main integration<br>
**Date:** 2026-11-10<br>
**Decider:** Codex under ADR-0018 owner delegation

## Context

The committed RP-01 package remains source 0.7/core 0.4/IR 0.1 while small fixtures
exercise later contracts. The signed [full-case audit plan](../evaluation/0065-rp01-current-contract-audit-plan.md),
`8728265`, precedes new probes. This audit changes only tests/docs; all production
rules, accepted contracts/artifacts and committed benchmark/guard bytes stay fixed.

Actual full-package experiments establish that current source 0.14/core 0.11/IR 0.4
can lower/check the graph after explicit retry syntax adaptation. Payment capture,
exact original-request retention and local matched late classification pass all
eleven native views without changing any existing provider/type/protection bytes.
An isolated finite active-work root still rejects ancestor reads/writes, but that
restriction does not block the demonstrated flat capture/retention body. Broader
preterminal commands/compensation are not required just to adopt these existing
full-case judgments. See the [critique](../evaluation/0065-rp01-current-contract-audit.md).

## Decision

Prioritize a separately frozen, controlled full RP-01 adoption checkpoint using the
existing accepted profiles. No new core, wire or permission is needed for the
proven scope. Explicitly promote source/companion/core/wire, adapt only the old retry
fault-source sentence to the supported general binding, add an exact terminal-source
descriptor for the unchanged payment provider and fresh local payment capture /
readonly original-request retention. A local late category may classify that
captured evidence against the retained original instruction, never the mutable
ancestor or a re-evaluated request. Keep its storage local; do not return a late
parent result, change ordinary disposition, clear cancellation or reopen a parent.

Reuse the existing payment completion receipt predicate, rebinding only result to
the normalized confirmed payload and payment_request to the readonly original
snapshot. Preserve every claim/revision/amount/currency comparison and all ordinary
guards. Record mismatched-evidence when receipt fields fail; retain the capture for
conflict review. Provider succeeded/confirmed is not automatically paid, and a
correct business tag alone is insufficient. No mismatch text or local finish settles
an outstanding conflict; actual accountable review/settlement remains a host gate.

The adoption must preserve an exact, tested historical source-0.7 counterpart,
original provider/type/clock/policy/input bytes and all 44 guard cases/46 values /
expected results. Repin only required candidate identities after actual generation;
never silently relabel historical evidence. Update the controlled generator,
manifest, reports, guard binding/test transport as explicitly required, with
complete old/new delta checks and final-head CI/comment review/signed merge.
Freeze that separate plan before changing committed package bytes.

## Alternatives and consequences

Another semantic/profile increment before using these already-supported judgments
would not address the demonstrated adoption gap. Full active work with ordinary
ancestor reads, richer P4 ownership and general preterminal/possibly-completed
compensation remain later if original cases require them. Do not add refund or
other out-of-scope business requirements to RP-01 merely because a prototype can.
Scope them from actual scenario gaps rather than a desired effect-class expansion.

The completed-diff review found that an initial tag-only classifier would call a
typed wrong-amount paid result paid. A production pure-evaluator counterexample
reproduces that weakness; the rebound receipt predicate rejects it. Thirteen typed
synthetic cases also cover wrong identity/revision/currency, problems, definitive
terminal categories and different retained revisions. This is pure conformance,
not actual provider evidence. The original guard corpus remains unchanged.

Actual accepted P6 activation/correlation/current authority/cutoff/immutable storage /
atomic handoff/all transitive settlement and truthful supported provider/normalizer
behavior remain live gates. Unknown is not terminal or safe retry, new business
work is not a technical retry, and late classification grants no dispatch. All
forty scenarios remain Partial, G1–G4 conditional; complete validator/benchmarks /
near-English/protected accessible visual/user/host/browser/independent/phase exits
stay open. Parent #46 remains draft/incomplete. No Phase 2 or phase report boundary.
