# ADR-0070: Publish purpose-only compensation activity identity

**Status:** Accepted under Project Owner delegation; effective on parent/main integration<br>
**Date:** 2026-11-11<br>
**Decider:** Codex under ADR-0018 owner delegation

## Context

ADR-0069 distinguishes prior activity identity from private value access and actual
eligible effect occurrence. Both raw C11 and source 0.15 refuse sibling-private
identity. Signed [plan](../evaluation/0070-compensation-identity-plan.md) `f18c783`
precedes production work; audit #84 passed final-head CI and merged before it began.
A source-only fix or silent reinterpretation of old core would violate those pins.

## Decision

Publish [core 0.12](../dialects/core-compensation-identity-v0.12.md), exact revision
`sha256:73158731c33084fde009abcc86530926447902609fda9535f04daa7c768c2007`,
on existing IR 0.4, requiring all eleven exact bases and uniform selected aliases.
Supersede only P1 `compensates` lexical identity visibility. Its exact ID must name
an existing capability activity in the same definition's node map. Preserve all
other type/kind/reference, ordinary lexical/private value/outcome/control/policy /
authority/protection/recipient/access rules. Cache selection once per static Check;
borrow the bounded node map and charge new identity work to the shared budget.

Inherit C11's finite owned-work proof and live host premises unchanged, including
immediate incoming source matching, capture-first compensator entry and provenance /
available local input/request/invalidation checks. Static same-site or sibling
identity does not grant an actually eligible prior effect, dynamic correlation,
temporal precedence, current authority, new logical key, provider event, private
value, dispatch, accepted ownership/handoff or settlement. Own effect class and
compensation purpose remain independent; no restoration/erasure is inferred.

## Options and consequences

Changing C11 would alter frozen evidence; generic global reference visibility would
expose unrelated data/control. Hoisting benchmark internals or omitting the purpose
changes meaning. The selected slot-specific raw rule supplies the necessary
identity contract with an explicit version and preserves old refusals. The narrower
owned-work proof can still reject a statically resolved target. General aggregate
ownership/possibly-completed compensation needs separate evidence and decisions.

Raw SDK only: no readable/frontend/CLI selection or benchmark adoption is added.
Next freeze a new readable profile with exact full qualification for nonlexical
prior identity, preserving generic lexical resolution and every old source refusal.
Then use genuine later full-case failures to choose further dependencies; never
generate full RP-03 IR through another route to claim admission.

Eight public SDK groups and one cumulative-work group plus three Python groups
cover scope/kind/missing/human/foreign/actual-use/class/purpose/private access,
exact pins/bases/wire/aliases, inherited refusals and old readable behavior. See
[evidence](../evaluation/0070-compensation-identity.md). Parent #46 remains draft,
forty scenarios Partial and G1–G4 conditional. Full validator/benchmarks/near-English
factoring/managed identities/protected accessible text-visual/actual user/host /
browser/independent/phase exits stay open. No execution or Phase 2 follows.
