# ADR-0067: Preserve the whole RP-03 draft and its actual capacity refusal

**Status:** Accepted under Project Owner delegation; effective on parent/main integration<br>
**Date:** 2026-11-11<br>
**Decider:** Codex under ADR-0018 owner delegation

## Context

After the controlled RP-01 checkpoint, the [0034 readiness sequence](../evaluation/0034-benchmark-readiness.md)
requires the original whole two-line order package. Signed plan `c63367b` precedes
code and probes. Its explicit draft now measures 505,980 bytes / 77,135 complete-line
tokens. Actual unchanged source 0.14 refuses tokens at 108626..108627 with no output.
There is no canonical candidate or whole semantic-stage evidence. All syntax beyond
the cutoff, control/lifetime/exceptional/settlement judgments remain unproved.

## Decision

Preserve the complete declared proposal, exact synthetic order/type/provider/source /
clock/input artifacts, portable explicit companion and actual native first refusal
in a dedicated stacked checkpoint. Retain original A–D and alternative responsibilities,
explicit fixed two-line scope, separate monetary/physical/compensation operations,
per-line outcomes and genuine external obligations. Do not silently narrow business
scope, infer safety from missing results, hide approval inside an adapter, raise
quotas, produce IR through a different route or call pure checks process admission.

Use existing source 0.14/core 0.11/intended IR 0.4 without changing accepted contracts
or production rules. Share configured bounded fixture formatting with RP-01 using
unchanged defaults; all 113 RP-01 current/history files and original guard bytes stay
fixed. Native bounded encoding checks cover new decimal/variant/nominal surfaces;
these are not a truncated order benchmark. Independent production SDK checks cover
all exact new nominal/provider/normalizer/clock resources. Twenty-two synthetic
production E1 receipt evaluations and eight recovery/partial-choice guard cases
cover exact fields, meaningful mismatches and missing-record hazards;
they do not create accepted facts or a transition/deduplication ledger.

Next freeze a separate source-profile capacity plan based on this actual package,
preserving the old source 0.14 refusal/quota and every prior profile/pin/meaning.
Measure native parser work, canonical output, shared semantic/report budgets and
Wasm effects; make no blanket budget increase or acceptance claim. The first admitted
parse may reveal syntax, qualification, control, metadata, invalidation or ownership
refusals; retain/fix each through accepted scope or a separate reviewed contract.
This decision accepts a draft checkpoint and evidence discipline, not a larger
language profile, complete validator or executable order support.

## Alternatives and consequences

Keeping only a small success-path fragment would omit the very parallel/compensation /
physical race constraints the benchmark must test. Raising an existing quota would
change a frozen profile. Dropping repeated protected labels or receipt clauses to
fit would change meaning. The full explicit text is expensive and unsuitable as
ordinary accessible authoring; reusable near-English declarations/summaries and
identity-managed editing remain a separate required Phase 1 deliverable. A capacity
increase is not a readability solution or representative-user evidence.

Current conservative root settlement needs actual retained original contexts, current
human/capability authority, positive stop/interception and capture eligibility,
accepted provider/clock truth/correlation/physical cutoff, immutable storage,
receiver acceptance/atomic handoff/all-transitive settlement and conflict review.
None is granted by a result tag, principal/receiver field, ownership claim or finish.
Unknown remains pending; repeated actual events require a real host ledger. All four
order scenarios/all forty corpus scenarios remain Partial, G1–G4 conditional, parent
#46 draft/incomplete. Complete RP-01/03/08/validator/text-visual/protected accessibility /
real users/hosts/browsers/independent/phase exits remain open. No Phase 2.
