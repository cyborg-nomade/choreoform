# ADR-0061: Select and disclose pre-capture entry explicitly in readable source

**Status:** Accepted under Project Owner delegation; effective on parent/main integration<br>
**Date:** 2026-11-10<br>
**Decider:** Codex under ADR-0018 owner delegation

## Context

ADR-0060 supplies a finite raw core-0.10 proof for read-only intermediate owned
entry before original capture. Source 0.12 still selects core 0.9 and must retain
its capturing-entry rule. Existing sentences already represent the new layout.
The signed [integration plan](../evaluation/0061-pre-capture-authoring-plan.md),
`73e2da2`, precedes production changes.

## Decision

Add [source 0.13 / companion 0.12](../authoring/profile-v0.13.md), explicitly
selecting exact existing core 0.10/IR 0.4 and all nine prior bases. Keep grammar
productions, ordinary roles/visibility/derived reads, qualified references, UTF-8
spans, package framing and quotas. Only the closed header/pair/core selection
changes. Libraries require exact supplied bytes; CLI embeds only known semantics /
core artifacts. Preserve every older profile/schema/artifact/report and benchmark.

Reuse the immutable SDK proof to disclose optional preCaptureEntry on new-mode
scope catalogue rows in the six native views including concurrency. Name entry,
captureWait and mandatory hostRequirements, tied to existing same-revision owner /
source/request/closure relations. Reused creators share declaration rows only.
Earlier views retain static declarations; old capturing-first cases/passive leaves
omit the new field. Keep inherited conditional proof/gates and distinct ordinary /
legacy/final continuation scope accounting. Reserve the complete row including new
requirements under the existing inherited-output/cumulative/final 1 MiB bound before
stdout. Do not rerun admission to serialize proof; return no partial report.

## Alternatives and consequences

An implicit source upgrade changes prior permission. A new sentence or wire field
adds no missing relation for this concrete layout. A metadata-only early-entry flag
would omit the actual conditional source/access/protection/invalidation proof and
might imply enabled work. Explicit selection plus immutable proof disclosure keeps
those boundaries observable. Command/compensation/new request/richer P4/ownership
judgments remain separate later dependencies.

Four frontend groups and one native unit group plus six limited independent Python
groups cover raw relation equality, all eleven SDK/native views, exact selection /
resources, original UTF-8 diagnostics, capture integrity/early reads, old omissions,
reused creators and valid combined whole-report exhaustion. A mismatched actual-use
wait endpoint already refuses during lowering; evidence records that real earlier
stage. See the [evaluation](../evaluation/0061-pre-capture-authoring.md).

Actual accepted occurrence-bound P6 registration/atomic handoff before entry,
current grants/open receiver/cutoff/disposal, exact correlation, immutable storage,
authenticated provenance and all activated transitive accountability/settlement
remain live host obligations. Query success, absent facts and graph outcomes supply
no activation, original source settlement or parent resumption. Finite shape proves
no liveness. Parent #46 remains draft, forty scenarios Partial, G1–G4 conditional;
complete validator/benchmarks/general near-English/protected accessible visual and
actual host/browser/user/independent/phase evidence stay open. No Phase 2.
