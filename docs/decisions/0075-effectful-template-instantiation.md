# ADR-0075: Adopt caller-local effectful instances in a separate benchmark change

**Status:** Accepted under Project Owner delegation; effective on parent/main integration<br>
**Date:** 2026-11-11<br>
**Decider:** Codex under ADR-0018 owner delegation

## Context

ADR-0074 requires effectful feasibility before full RP-03 instantiation. Signed
[plan](../evaluation/0075-effectful-template-instantiation-plan.md) `9149340`
precedes these probes, after #89's final-head CI and parent merge. The complete
bounded source uses two caller-local service definitions, typed record ports,
matching receipt/request completion predicates, local reconciliation/capture /
readonly original requests, distinct capability/effect/wait identities and exact
fictional provider recipient/source revisions. All eleven native views pass for
three classes with and without explicit compensation declaration identity.
The [critique](../evaluation/0075-effectful-template-instantiation.md) records
isolated refusals, transitive invalidation and the conditional proof boundary.

## Decision

Keep all production and current/historical benchmark bytes fixed in this proof.
Select **caller-local source-generator instantiation under existing contracts**
for a new separately signed full RP-03 adoption plan. Coordinate local identities,
ports, lexical policies, effect/wait endpoint ownership, protected resource
recipient claims/revisions and input/control invalidation. Preserve previous
artifacts and business predicates; inspect every full-case stage honestly.

A shared provider descriptor can serve distinct logical capabilities when its
exact protected recipient claims match. Reusing one capability/effect/wait across
different actual closure owners does not pass this bounded source. New fictional
provider/source revisions may be needed for the benchmark; those are explicit
claim changes, never actual provider approvals, aliases or authority. Preserve
same-parent reuse where its relationships remain valid.

## Alternatives and consequences

| Option | Decision |
| --- | --- |
| Coherent caller-local body/capability/effect/wait/storage identities | Selected for later full generator adoption |
| Reparent one shared record or reuse an exact endpoint across owners | Rejected by the bounded relationships; can also break lexical provenance |
| Frontend parent-check bypass or implicit private reads | Rejected; conflicts with current source/raw contracts |
| New generic reusable-template/recipient-alias contract | Not justified by this bounded proof; separate version/ADR if actual requirements demand it |

No safety claim follows from a class or compensation link. A compensation is new
work, technical retry preserves its own logical effect, and live prior eligibility,
current authority, exact original request/capture correlation, fresh occurrence
storage, cancellation/closure cutoffs, receiver/registration, conflicting evidence,
atomic ownership handoff and every transitive obligation remain required.
Final reports are non-executable and retain uncovered reconciliation nodes and
conditional local checks. No full RP-03 candidate, changed guard or execution is
produced here. Parent #46, forty Partial scenarios, G1–G4/full/optional/RP-08 /
validator/near-English factoring/managed protected accessible text-visual/actual
users/hosts/browsers/independent/Phase 1 exits remain open. No Phase 2.
