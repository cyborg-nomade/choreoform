# ADR-0071: Bind exact readable compensation activity identities

**Status:** Accepted under Project Owner delegation; effective on parent/main integration<br>
**Date:** 2026-11-11<br>
**Decider:** Codex under ADR-0018 owner delegation

## Context

Core 0.12 supplies purpose-only static prior-activity identity, independently of
lexical access and actual eligible occurrences. Source 0.15 deliberately retains
its old private-reference refusal. Signed [plan](../evaluation/0071-compensation-identity-authoring-plan.md)
`30ac848` precedes code/probes; raw #85 passed final-head CI and merged before work.

## Decision

Publish explicit [source 0.16/companion 0.15](../authoring/profile-v0.16.md), selecting
exact C12/IR 0.4 and all eleven bases, with unchanged grammar productions/schema
structure/inherited features and budgets. Change only `Compensates` binding:
unqualified references stay lexical, qualified references use an exact complete
scope path through this definition's root. Direct bounded declaration/name lookup
disambiguates shadows; partial/foreign/missing/wrong-kind paths refuse. Check the
target capability-activity kind/mode after node binding, at its exact source span,
using the existing cumulative dependency-work budget. `none` remains null.

Keep generic resolution and every other private reference slot unchanged, including
the separate actual-use wait endpoint. Preserve C11 immediate incoming-source owned
proof and all live eligible effect/occurrence/input/basis/current authority/new logical
effect/key/storage/accepted event/ownership/handoff/settlement obligations. Static
same-site or sibling identity proves none of those. Earlier source/core artifacts,
quota/semantic/report meanings and all committed benchmark bytes stay fixed.

## Options and consequences

A generic name scan would make captions ambiguous and expose private slots. Reusing
the wait-endpoint exception would conflate separate contexts. Silent source 0.15
changes or hoisted benchmark internals would alter old evidence. Exact purpose-only
qualified binding supplies the narrow requirement and stable managed identity while
leaving values/control private. Kind checks happen before new-profile candidate
formation; old profiles retain their earlier lowering/checking staging.

Four public SDK groups, expanded lexer boundaries and seven Python/native groups
cover paths/shadows/Unicode/kind/human/old-new privacy, pairs/core/bases/future, exact
format/reparse and all eleven bounded checking/advisory views. Small candidate bodies
differ from old only by the selected core and resulting revision; report meanings
are unchanged after that exact identity translation. Whole RP-03 still has no IR:
the genuine later refusal is `symbol-mismatch at 0..0`. Python recognition separately
hits its unchanged state limit. See [evidence](../evaluation/0071-compensation-authoring.md).

Next freeze a whole-case symbol/companion binding audit to identify that failure's
cause before choosing a correction. No full-case bypass/adoption or aggregate
ownership expansion follows. Exact qualification is not the complete near-English
deliverable: reusable wording, managed identities/protected accessible editing/export /
text-visual and actual user evidence remain explicit Phase 1 work. Parent #46 draft,
forty Partial, G1–G4/validator/full/optional/RP-08/external/phase exits open. No Phase 2.
