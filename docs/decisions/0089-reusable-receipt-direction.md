# ADR-0089: Expand typed pure receipt recipes before considering shared work

**Status:** Accepted direction under Project Owner delegation; effective on integration<br>
**Date:** 2026-11-13<br>
**Decider:** Codex under ADR-0018; no personal owner or independent approval

## Context and decision

Signed [scope89](../evaluation/0089-reusable-receipt-critique-plan.md) `0e4c706`
follows verified PR #103 merge `46e6566e1f0c90f2d027911b40af466fad97d1e5`.
Signed [critique](../evaluation/0089-reusable-receipt-critique.md) `d683bf7` precedes
evaluation tooling and any future production implementation. Both actual current
packages stay exact; no accepted grammar/schema/core, runtime or quota changes here.

Select **typed source-only pure Boolean recipes expanded at each use** as the next
separately contracted direction. Prefer explicit instruction and already-unwrapped
evidence-representation inputs, with explicit operation/phase values. Keep nominal
membership/invariants and payload/tag dispatch explicit in the caller. No recipe
name grants trust, authorization, receipt truth, retry or execution admission.

A finite read-only experiment on the actual complete RP-03 IR reconstructs all55
capability-result case predicates exactly using two complete four-input templates:
26 thirteen-comparison cases and29 fourteen-comparison cases. All25 activity/work /
capability/request identities remain distinct. All23 nominal result types pin the
same exact type contract and share one complete structural representation, while
retaining separate nominal names and invariants. All25 input types are equal.
The helper inputs can therefore use the explicit representations already unwrapped
in the old AST, without a new cast or implicit nominal membership.

Balanced conjunction matters: adding a reason clause to the thirteen-leaf tree
would not yield the exact fourteen-leaf balanced tree. Preserve two complete
predicate shapes rather than assuming algebraic equivalence is full IR identity.
The experiment substitutes explicit AST terms, never strings or inside literal
values/type descriptors; reconstruction of every actual case is checked. It is
not implemented language, native helper typechecking or measured future reduction.

## Alternatives and implementation boundary

New IR calls would need a separate core/schema/runtime/dependency/call-context
contract and deliberately changed revisions; existing parameter records do not
provide that contract. Hygienic scoped work/service templates are broader: fresh
managed storage/work/endpoint/occurrence IDs, direct-child ownership, exact provider
claims and lifetime/capture/compensation proof are still required. Protected
inspection/formatting remains necessary but does not remove repeated source.

The next production scope must publish an explicit source/companion contract
before implementation, retaining C12/IR0.4 and all older profile meanings. Define
pure closed typed inputs and source-only managed recipe/parameter identities;
validate unused/forward/cyclic definitions and lexical/nominal/type provenance.
Forbid ambient cells/facts/authority and implicit capture/defaults in a definition.
At uses, infer/check arguments and expand hygienically into the real caller before
actual native typing/reads/invalidation/protection checks. Literal opacity and
complete current balanced AST/IR/revision identity must hold in finite variants.
Charge cache/use/argument duplication cumulatively to existing depth/work/node/byte
limits; fail privately with no partial candidate. No public evaluator or IR call.

Measure full source plus definition/use overhead on actual RP-01/03 variants
before adoption and assess readable worked alternatives. A smaller expanded JSON
experiment, same-shaped producer helper or size upper bound is not a savings or
user-comprehension result. RP-01's principal/current-policy/approval checks must
remain; do not force order-specific receipt logic onto human work.

Full RP-08 remains Phase1: dynamic scope/work, protected custody, changing severity,
contradictory facts, guarded containment and outage/handover cannot be represented
by a Boolean helper alone. General managed protected accessible editing/export /
text-visual and actual representative-user evaluation remain open alongside it.

Required relevant tests/CI, separate completed-diff automated review, all comments /
CodeRabbit audit and signed expected-head merge precede integration. All40 scenarios
remain Partial, G1–G4 conditional, parent46 draft and conservative external-region
refusal unchanged. No actual provider/host/browser/user/independent evidence or
phase exit; no Phase2.
