# ADR-0064: Select and disclose finite owned work in readable source

**Status:** Accepted under Project Owner delegation; effective on parent/main integration<br>
**Date:** 2026-11-10<br>
**Decider:** Codex under ADR-0018 owner delegation

## Context

Core 0.11 adds finite capture-first commands/explicit compensators and supported
pure local input construction. Source 0.13/core 0.10 must keep its old restrictions.
Existing sentences already represent the new shape. The signed
[integration plan](../evaluation/0064-finite-work-authoring-plan.md), `bf65a8d`,
precedes production changes.

## Decision

Add [source 0.14 / companion 0.13](../authoring/profile-v0.14.md), explicitly
selecting exact existing core 0.11/IR 0.4 and all ten inherited bases. Grammar
productions stay identical to source 0.13; roles/visibility/complete derived reads,
qualified references, original UTF-8 spans/package framing/quotas remain. Library
users supply exact artifacts; CLI embeds only known semantics/core bytes. Actual
provider/source/type/history metadata stays explicit. Earlier profiles/artifacts /
reports and committed benchmark bytes remain fixed.

The six native views including concurrency reuse immutable proof and add optional
work on new-core intermediate scope catalogue rows: site/capability/input expression /
effectClass/compensates/mandatory hostRequirements. Query keeps uncompensated
read-only inquiry meaning: commands and compensators show query=null. Old-core /
passive-leaf rows omit work. Keep inherited preCaptureEntry/conditional checks/gates
and distinct final continuation scope accounting. Reused creators share declaration
rows only. Reserve complete work rows after inherited output under existing
cumulative/final 1 MiB bounds before stdout; no partial report or admission rerun.

Use clear command captions and fresh exact synthetic provider/general/terminal
resources for a small capturing-first compensator with capture-derived integer input
and a differently typed child request. Its own irreversible class and compensation
link remain independent; the original provider is compensatable. No label establishes
business eligibility, authority, implemented provider behavior or accepted execution.

## Evidence and consequences

Four frontend groups, one native unit group and six limited Python groups cover
all eleven SDK/native views, exact raw reference relations/resources/pairs, type /
child seed differences, all six class/link combinations, formatting/Unicode/qualified
names/original UTF-8 diagnostics, inherited real refusals, old omissions/shared rows
and valid combined report exhaustion. The small combined history/new-work form
passes; the large valid form lowers then every report refuses before stdout. See
[evidence](../evaluation/0064-finite-work-authoring.md). This is static synthetic
integration evidence, not actual observations or user/host/independent review.

An implicit upgrade would change prior permission; new syntax or wire fields add
no missing relation here. Broader preterminal/possibly-completed compensation and
P4/ownership/complete benchmark judgments remain later dependencies. Actual accepted
P6 activation/current authority/open receiver/cutoff, new logical effect/key, exact
request/input/value/occurrence/digest/attempt, immutable storage/full provenance,
implemented provider promises, eligible prior compensation/business conflict and
atomic handoff/all activated transitive settlement remain live host gates. Reports
enable no work, settle no original effect, resume no parent and prove no liveness.
Parent #46 remains draft, forty scenarios Partial and G1–G4 conditional; complete
validator/benchmarks/general near-English/protected accessible visual and real
host/browser/user/independent/phase evidence stay open. No Phase 2 or exit.
