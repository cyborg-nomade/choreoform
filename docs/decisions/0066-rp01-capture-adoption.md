# ADR-0066: Publish the full RP-01 typed late-capture checkpoint

**Status:** Accepted under Project Owner delegation; effective on parent/main integration<br>
**Date:** 2026-11-10<br>
**Decider:** Codex under ADR-0018 owner delegation

## Context

[ADR-0065](0065-rp01-current-contract-direction.md) demonstrated actual full RP-01
capture, exact original-request retention and receipt-matched local late records
using existing contracts. The [separate controlled adoption plan](../evaluation/0066-rp01-capture-adoption-plan.md)
was signed/pushed as `262fdc0` before generator or benchmark changes. Repeatedly
expanding small semantic fixtures instead would leave this demonstrated full-case
integration gap open. No new core/wire/grammar/permission is necessary for this scope.

## Decision

Publish the generated synthetic checkpoint with explicit source 0.14 / companion
0.13 / core 0.11 / IR 0.4 selection, unchanged original resources/ordinary graph /
guards, and only the demonstrated payment recovery addition. Use the frozen official
identities, exact terminal-source descriptor for the unchanged provider, fresh local
typed capture, readonly exact original request and local receipt-matched category.
The existing recovery wait now flows through local classification to its same finish.
The classifier reuses the original completion AST and preserves every receipt field
comparison, substituting only captured confirmed payload and retained original
request. Mismatched-evidence retains its capture for accountable conflict review;
recording that text or finishing does not settle any conflict. No ancestor/ordinary
parent result is written, parent resumed or cancellation cleared.

Preserve a generated exact historical source-0.7 checkpoint with its original
source/companion/candidate/manifest/resources/inputs/ten reports. A contextual history
README identifies that scope; original manifest/report bytes are not relabeled.
Historical profile/schema/SDK/native regression tests explicitly select the archive.
Current adoption tests select the current package and cover full-body delta,
regeneration/pins/protection/coverage/refusals/formatting/quotas and all eleven actual
checking/advisory views. Only the two candidate identity fields change in the original
44-case/46-value guard catalogue. The production pure-evaluator harness loads actual
current IR 0.4 and exact inherited artifacts, matches the thirteen-case synthetic
corpus to the compiled official classifier and evaluates it without a new public API.

## Alternatives and consequences

Keeping RP-01 on old profiles would preserve the adoption gap identified in 0065.
Silently replacing historical expected values/identities would destroy evidence;
the explicit archive costs additional fixture bytes and requires deliberate test
selection. Both current and historical packages regenerate through the actual native
frontend with exact byte comparison. General migration/export/editing stays separate.
The bounded fixture assembler is not a general language editor or reference engine.

The new terminal descriptor is static metadata; it creates no actual provider fact.
Current flat owned proof supplies source/control protection labels, not live ancestor
values. The retained-seed body remains uncovered by legacy reconciliation availability;
two other surviving declarations remain isolated. Accepted P6 activation/current
correlation/authority/cutoff/immutable storage/receiver acceptance/atomic handoff/all
transitive settlement and accountable conflicting-evidence review remain host gates.
Unknown stays pending; categories grant no retry/new dispatch or renewed approval.
No refunds or other new business requirements are added to the original case.

All four RP-01 scenarios and all forty corpus scenarios remain Partial, G1–G4
conditional, parent #46 draft/incomplete. Next reassess the remaining actual original
scenario and complete-validator/RP-03/08/text-visual dependencies from the integrated
checkpoint before another permission expansion. General tool-managed near-English /
protected accessible editing, actual host/browser/user/independent evidence and
Phase 1 exits stay open. Agent self-review is not independent/human or personal owner
review. Stop at an honest phase report for owner approval; no Phase 2 is authorized.
