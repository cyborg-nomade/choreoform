# ADR-0059: Enable useful owned read-only entry before broad command work

**Status:** Accepted under Project Owner delegation; effective on parent/main integration<br>
**Date:** 2026-11-10<br>
**Decider:** Codex under ADR-0018 owner delegation

## Context

Core 0.9/source 0.12 checks finite read-only surviving continuations, but its
capturing entry accepts only terminal facts. Unknown/acknowledged provider
observations have no terminal tag. General new command permissions would not solve
useful inquiry while the source effect remains unresolved. The
[signed audit plan](../evaluation/0059-owned-entry-command-audit-plan.md), `d49a96f`,
precedes eight genuine SDK/frontend probe groups and a
[critique](../evaluation/0059-owned-entry-command-audit.md). Production behavior and
all accepted contracts/artifacts remain fixed in this audit.

## Decision

Prioritize an explicit finite read-only owned entry contract before general
command/compensation. Freeze a separate signed raw implementation plan for a new
exact core on existing IR 0.4, preserving all earlier meanings. Existing entry /
flow/request/source/effect-wait/closure relations represent the concrete proposed
query-before-original-capture layout; no missing serialized relation has been found
for this narrow conditional stage. Add a wire field only if implementation supplies
a concrete gap and a signed refinement. Readable selection follows separately.

The new family may permit local entry/query work before its original source capture,
while retaining the unique actual-use timerless capture wait in the designated P6
body and proving its reachability. Captured result reads remain unavailable before
acceptance. Seed only the exact immutable original request, after empty pre-entry
write access and actual accepted occurrence-bound P6 registration/handoff. Do not
derive activation from an ordinary graph outcome, missing fact, true policy or
metadata declaration. New work needs fresh current grants and its own open scope;
registration/handoff must respect cancellation/closure cutoff and disposal.

Preserve all actually activated transitive source/query effects, subscriptions and
children under one accepted accountable owner. Missing receiver acceptance leaves
the old owner accountable; no capture/query/finish proves terminal disposal. A query
success does not manufacture original source success, return a parent result or
clear cancellation. Keep exact request/value/input/occurrence/digest/effect/key /
attempt correlation, fresh immutable storage and authenticated full provenance as
explicit live host gates, not static proof parameters or generated receipts.

Queries remain supported read-only, one-attempt, timerless, uncompensated and
exactly bound to their own original request. Retain complete input/policy/source /
fault/control/provider/creator-owner labels, exact capability recipients, local
storage, all-declaration/child checks, strict invalidation, bounded shared analyses
and separate ordinary/legacy/old-flat coverage. P4 handler activation/history and
P6 surviving ownership remain distinct; conditional query coverage cannot borrow
ordinary history-entry proof. Expose entry/capture relations without altering old
reports. The audit itself adds no production permission or new accepted core.

## Alternatives and consequences

Effect-class loosening alone leaves the entry barrier and command/key/authority /
compensation obligations unproved. Same-scope terminal callback work conflicts with
terminal disposal; later facts need a separately linked instance. Ordinary parent
work cannot substitute for late surviving work. Combining a P4 handler with its P6
owner changes independent activation/lifetime rules and already refuses at
fault-entry-creator. A new typed owned-history field adds semantics not needed by
the concrete read-only inquiry shape; defer until a demonstrated requirement.

The next contract remains deliberately narrow: command/compensation, arbitrary
new request construction, richer handler/ownership contexts and general recovery
remain later work. [The Roadmap](../../ROADMAP.md) must keep those and useful
preterminal inquiry explicit. All actual host authority/cutoff/handoff/all-settlement,
complete validator/benchmarks/general near-English/protected visual editing and
real host/browser/user/independent/phase evidence stay open. Parent #46 remains
draft/incomplete, every scenario Partial and G1–G4 conditional. No Phase 2 or exit.
