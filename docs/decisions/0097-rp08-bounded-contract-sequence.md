## Decision

Select **definition-bounded whole-case evidence plus separately versioned minimal
missing contracts**. Preserve the complete brief, including ad hoc authorized work
and outage/confidentiality. Do not relabel a fixed subset, manual/provider placeholder
or pretty diagram as its implementation. General adaptive runtime definition/code
injection is not the next implementation; reconsider it only against a demonstrated
requirement the smaller accepted meaning cannot meet.

The next dedicated scope publishes an exact foreign evidence/history representation
and admission contract before any implementation. It must separate immutable source
records and known causal/clock facts from current trusted acceptance, decision/effect
authority and executable state. Define source/event identity, provenance, exact
payload/profile support, duplicates versus conflicts, partial order/unknowns,
external-reference boundaries, timestamps, privacy, error/size/work limits and stage
claims. Do not infer chronology from timestamp/ID/storage order. Representation
validation cannot authenticate an untrusted event, accept a historical business
decision, rewrite terminal history or dispatch/replay an action. No runtime engine
or generic history importer is delivered by this decision.

Subsequent dependencies remain within Phase1:

1. Resolve exact keyed batch/result/retention/lifetime and definition-bounded ad hoc
   work semantics, reusing accepted typed captures/owned work when applicable.
   Required human behavior remains semantic. Preserve old closed interfaces,
   changed-input/new-work and no implicit parent-output rules; any needed extension
   gets separate exact publication and implementation. Whole parallel effect proof
   still requires actual original snapshot/canonical physical/accepted surviving-work
   premises, not different strings, nominal membership or C13 metadata alone.
2. Define/enforce audience artifact/evidence projections independently of complete
   documents, runtime-data protection and read/edit/export. Cover metadata/topology/
   timing as well as content, current trusted access and stale bindings; no hidden
   model reconstruction or unsupported redacted editing/export.
3. Build the complete RP08 source/companion/resources/IR/scenario/report package,
   mapping every inventory row to actual declarations/tests and honest open host
   obligations. Measure real whole files under existing bounds; no placeholder or
   generated event/participant observation stands in for an absent result.
4. Complete broader managed operations, full validator/actionable field/argument
   diagnostics/conformance/negative examples and three-process both-form cycles,
   then actual representative-user/independent and required host/provider evidence.
   Continue independent preparation before reporting a genuine external blocker.

## Alternatives and consequences

The critique compares a fixed existing-template skeleton, the selected bounded
contract sequence, a general adaptive engine and dropping difficult requirements.
The skeleton can aid construction only if its incomplete scope is explicit. The
general engine adds unjustified typing/revision/authority/runtime cost now. Dropping
requirements contradicts the brief/roadmap and is rejected. The selected sequence
requires more explicit contracts and proof work; it offers no immediate gate upgrade.
Its benefit is concrete falsifiable boundaries before new semantics or code.

This ADR changes no syntax, IR/API schema, native behavior, accepted profile/quota,
provider permission, benchmark/corpus/report/guard/receipt byte or execution stage.
It does not itself admit a history schema or a full process. Scope97 is documentation /
design only. Exact contracts/resources/vectors and subsequent production/native /
Wasm/visual implementations require separately signed scopes/publications/reviews.
Rust and one shared semantic model remain the accepted implementation direction.

All40 scenarios remain Partial and G1–G4 conditional; all six open Phase1 headline
criteria remain. The executable IR completion gate is not bypassed. No standardized
visual notation before usability testing, no user/independent/host evidence invented,
no Phase2/new phase chat or Phase1 completion. Review and required final-head CI /
full comment audit/expected-head signed merge precede integration; the owner still
approves the honest end-of-phase report.
