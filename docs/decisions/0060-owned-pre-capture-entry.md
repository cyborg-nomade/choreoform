# ADR-0060: Check finite read-only owned entry before source capture

**Status:** Accepted under Project Owner delegation; effective on parent/main integration<br>
**Date:** 2026-11-10<br>
**Decider:** Codex under ADR-0018 owner delegation

## Context

ADR-0059 identified a useful inquiry before an unresolved original source supplies
its terminal capture. The signed [raw implementation plan](../evaluation/0060-owned-pre-capture-entry-plan.md),
`57345e2`, precedes production changes. Existing IR 0.4 represents the narrow shape;
no new serialized relation is required. Old capturing-entry paths remain fixed.

## Decision

Publish [exact core 0.10](../dialects/core-owned-pre-capture-v0.10.md), requiring all
nine inherited bases and uniform selected aliases on IR 0.4. Only an intermediate
designated P6 surviving body with its own direct designated child may start at local
compute, decision or its one supported read-only query before its original capture.
Bind the actual source capability's effect reconciliation policy to its unique,
same-body, timerless capture wait and prove that wait reachable. Its capture target
must be local, uninitialized and written only by that wait. Terminal leaves and old
flat owned proof keep their capturing-entry restrictions.

Keep conditional proof separate from ordinary and legacy coverage. Seed only the
exact readonly original accepted request after empty pre-entry access; preserve
complete source/input/policy/control/provider/owner provenance, actual capability
recipients, local availability/protection and strict invalidation. The query remains
one-attempt, timerless, uncompensated, exact request input, with a supported general
source matching its provider. Index waits and writers once per bounded analysis,
share immutable creator templates and charge cumulative work/publication budgets.
Expose immutable optional entry/capture-wait relations; do not change old native
outputs. Readable selection follows a separate explicit source profile.

Actual accepted occurrence-bound P6 registration/atomic handoff must precede new
entry, with fresh current grants, an open/noncancelled receiver and respected
source cutoff/disposal. No metadata, true predicate, missing fact or query success
enables work. Failed receiver acceptance leaves the old owner accountable. Preserve
the original unresolved source and every actually activated transitive effect,
subscription and child until accepted settlement. Reports provide no events, values,
storage, grants, accepted receipts, parent resumption or liveness. Retain exact
occurrence/request/input/value revision/digest/effect/key/attempt correlation and
fresh immutable storage/authenticated provenance as live host obligations.

## Alternatives and consequences

Requiring capture first prevents this inquiry. Treating unknown as a terminal tag
would invent a fact. A general command or arbitrary request permission adds identity,
authority and compensation obligations this proof does not discharge. A runtime
activation field is unnecessary for a conditional definition judgment and would not
supply actual acceptance. Keep commands/compensation/new request construction and
richer P4/ownership contexts as separate later work.

The completed-diff review found that an initializer or compute could counterfeit a
capture before its wait. A genuine SDK regression failed before the new capture-
target integrity check and passes after it; the restriction belongs only to the new
mode. This is delegated agent review, not independent or human review. See the
[evidence](../evaluation/0060-owned-pre-capture-entry.md). Parent #46 remains draft;
all forty scenarios remain Partial, G1–G4 conditional, and complete validator /
benchmarks/general near-English/protected visual editing and actual host/browser /
user/independent/phase gates remain open. No Phase 2 or exit is implied.
