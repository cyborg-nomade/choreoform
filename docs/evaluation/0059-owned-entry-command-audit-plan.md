# Owned unresolved work and commands: frozen contract audit plan

**Date:** 2026-11-10<br>
**Baseline:** `2cdcfccb30321597fee25528294d49da6850e0cb`, draft #46 after PR #73<br>
**Authority:** ADR-0018 / ADR-0057/0058; audit only, no production permission change

Use a dedicated stacked audit branch/PR and ADR-0059. Before loosening the read-only
family or adding a new semantic/wire contract, critique the accepted ownership,
entry/protection/source and command/compensation requirements using actual current
SDK probes. Change tests/docs/roadmap/progress only. Keep every production behavior,
accepted core/wire/source/schema/hash/artifact and committed benchmark/report byte
fixed. Freeze this plan with sign-off before adding probes; acceptance is under
owner delegation, never personal owner or independent review.

The current finite family enters through a timerless capture of terminal source
facts. Provider acknowledged/unknown observations have no terminal declaration.
Distinguish definition-level possible coverage from actual availability and work
registration: a passing static chain does not mean a query can run while its source
effect is unknown. Establish this boundary explicitly before designing permitted
commands or useful unresolved-effect inquiry. Preserve pending/unknown versus
ordinary success/no-effect, all actual transitive subscriptions/effects/children,
monotonic cancellation and closure cutoffs, atomic accepted handoff and terminal
settlement; do not manufacture a result or grant to make an example progress.

Use small synthetic metadata with exact fresh pins and the real composed SDK,
reusing the existing raw/readable two-level fixture where possible. Confirm the
current read-only baseline and terminal-tag/type/source relations. Probe a matched
original irreversible source followed by permitted read-only work, a matched new
irreversible/compensatable provider/effect/source/capture, and exact earlier static
versus conditional refusals (including wrong idempotency/provider/compensation
bindings). True completion or policy expressions are not runtime evidence. Do not
broaden accepted benchmark metadata or relabel a command/unknown as read-only /
terminal. Fresh synthetic probes must state their explicit recipient/authority
premises and retain no actual events, values, storage, grants or receipts.

Probe alternatives for entering owned work before terminal facts: passive/compute
entry instead of capture; typed provider-fault history; combined original request
and fault-history binding; separate P4 handler and P6 surviving owner rather than
assuming identical activation/lifetime; and pure local request projection versus
current exact retained-request input. Evaluate only concrete supported paths;
record the first real refusal and separately inspected downstream predicates,
without pretending an earlier rejection executed a later proof. Preserve all
possible incoming emitter/full handler-stack contexts, conditional source coverage,
empty pre-entry access, complete original request/input/policy/source/fault/control /
provider provenance, exact recipients, readonly immutable storage and strict
invalidation. No ordinary resumption, hidden invocation/parallel work, fabricated
snapshot or empty provenance fallback is permitted.

Critique at least: broadening effect class alone; same-scope terminal callback work;
combining P4 handler and P6 lifetime; a separate explicit owned registration/entry
relation; and ordinary parent activity as a purported late-resumption substitute.
Decide the next smallest useful independent implementation under delegation, with
requirements, alternatives, consequences and explicit remaining limits. Existing
IR 0.4 relations may suffice only if exact entry/source/ownership/cutoff semantics
are unambiguous. Identify a concrete missing serialized relation before selecting
a new wire field; do not assume a new wire or reuse unknown annotations as meaning.
Conversely, do not weaken an accepted field's meaning to avoid explicit versioning.
New work must have new logical effect/key identity, actual current authority and
exact request/value/input/occurrence/digest/attempt correlation; compensation must
bind the prior occurrence, create new authorized work and never erase the old effect.

The critique is not an implementation or phase exit. Record unresolved command /
compensation and useful preterminal owned work explicitly in the Roadmap. Freeze a
separate signed implementation plan after this audit before changing production.
Include genuine fixture probes, relevant native/Wasm/all Python/final-head CI,
separate completed-diff delegated review, all unresolved threads/CodeRabbit summaries,
expected-head signed merge and durable progress/next dependency. A skipped bot adds
no review evidence. Parent #46 remains draft/incomplete; all forty scenarios Partial,
G1–G4 conditional. Complete validator/benchmarks/general near-English/protected visual
editing and actual host/browser/user/independent/phase gates remain open. Finish
independent work; do not report hypothetical external blockers or start Phase 2.
