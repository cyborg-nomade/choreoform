Project Owner's goal is text as close to plain English as practical for broad
accessibility; technical hashes/IDs/JSON and compiler internals belong in managed
bindings, not ordinary authoring flows. Keep precise deterministic controlled
English, explicit actor/policy/conditional meaning and progressive disclosure.

Measure actual RP-01/RP-03 source/package sizes, tokens and repeated type, service,

benchmark or near-English/user-evaluation exit.

local reusable type/expression/protection names, hygienic parameterized scoped

material. Favor the smallest coherent first implementation that has meaningful
whole-process reduction and transparent meaning. Do not choose terse punctuation
or opaque domain verbs simply to reduce bytes. Preserve user-visible authority,
protection, original-request/uncertainty/compensation/ownership and refusal context.

inactive syntax/expansion probe is explicitly labeled and follows a signed critique
checkpoint before code. If claiming source/IR equivalence, actually expand/lower /
validate the stated finite cases with existing tools; otherwise label examples
paper-only. No fake participant feedback or invented comprehension measurements.
Record byte/token/expansion/diagnostic evidence proportionally to what runs.

capability/work/wait/retention/capture occurrence relationships, P3 definition-
context recipient claims and exact resource pins. Reuse must instantiate correct

silently rewriting/widening provider permissions. Capture avoidance, lexical
privacy, qualified purpose-only compensation targets, stable managed identity /
source maps, ambiguity/refusal and cumulative expansion/output budgets are required
criteria. Do not turn text substitution, backend Python generation or an unchecked
macro into evidence of a safe authoring implementation.
