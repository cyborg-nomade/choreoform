# Finite read-only surviving continuation evidence

**Date:** 2026-11-10<br>
**Baseline:** `ae28e9467724d1acf681ac0800f82e49485aff8c`, draft #46 after #71<br>
**Authority:** ADR-0018 / [ADR-0057](../decisions/0057-owned-readonly-continuations.md)<br>
**Frozen plan:** `22654bb`, [plan](0057-owned-readonly-continuations-plan.md)

Exact core 0.9 `sha256:5faaf24217bcc5644a9ce5975b2c6ad7074d0197d39a73ab648d6cb3a9ced87f`
requires all eight bases and existing IR 0.4, with uniform selected aliases. Earlier
source/wire/core/artifact meanings stay fixed. Static retained requests may have
exactly their designated reconciliation child; all original local/type/readonly /
capture/provider/visibility/creator/handler/port barriers remain in force.

The distinct immutable OwnedContinuationReport describes finite conditional trees
rooted at ordinary synchronous creators. Intermediate bodies have one timerless
capturing entry, one exact readonly original-request cell, one read-only query and
its designated surviving child. Terminal leaves remain passive. Query work is one
attempt, without clock/timer/compensation, with exact supported general fault source
and input reading only its own original request. All declarations are inspected.
Root and conditional bodies refuse foreign node storage. Query sources require
ordinary root coverage or actual earlier conditional coverage in their parent.

The shared owner-before-child analysis checks empty pre-entry write access, fresh
locals, every capture/query/branch/initializer transfer and strict invalidation.
Complete source/input/policy/control/provider/owner labels survive as provenance,
never as ancestor values or cached grants. Each query's actual capability ID must
occur in every retained/input/access/control envelope's recipient set, before any
result transfer. This explicit new-core check closes an audit gap: earlier result
publication checking is insufficient to prove provider dispatch eligibility, and
provider resultProtection is not an input-recipient contract.

Templates are shared across creators; per-level provenance is moved/consumed instead
of cloning the entire map. Entry graph, flow/context, template/index copying and
gate/aggregate publication are bounded cumulatively under existing stage allowances.
The report retains access/provenance/invalidation and source/query/request/child
relations. Scope.closure() is the source owner's incoming reconcile policy.
Ordinary/legacy/old-flat checked sets remain separate. The final chain exposes
continuation_scopes separately and avoids rerunning legacy zero-seed checks on
already-proven conditional bodies; their nodes remain legacy-uncovered.

Seventeen integration groups and three unit groups exercise:

- actual complete composed SDK passes for two- and three-level chains, local
  captured branches, exact requests and distinct conditional/legacy coverage;
- reused ordinary creators with immutable shared templates and mandatory fresh
  occurrence storage, without invented actual values or host acceptance;
- every inherited pin, uniform/mixed aliases, old-core nested rejection, unvisited
  ordinary/conditional sources and unvisited extra queries;
- missing/wrong request/capture, initialized storage, foreign root/conditional
  reads/writes, extra lexical children, complete query reads and transformed input;
- self/peer/ancestor seed-access refusal, source/control/constant initializer leaks,
  narrowed branch recipients (including a genuine query with no result cell) and
  strict invalidation at each level;
- matching genuine irreversible provider/effect/source/capture metadata refused as
  new work, unsupported general source/retry, and conditional query fault origins
  retained as unexplored rather than borrowed ordinary history-entry coverage;
- cumulative index/template, graph, provenance-copy and final aggregate-publication
  exhaustion without partial reports or extra creator rows.

The ancestor/self permission cases explicitly record earlier static information-flow
refusal where a changed root query input policy blocks reaching conditional entry;
the leaf cases genuinely reach empty pre-entry access refusal. No test substitutes
an expected later diagnostic for the actual stage. The three-level positive uses
fresh synthetic provider/source metadata explicitly permitting its third capability;
no accepted benchmark metadata is broadened. The negative command likewise has
matching metadata, so a mislabeled provider cannot explain its refusal.

A committed synthetic definition with exact metadata bytes and eleven isolated
mutation vectors is consumed by the real SDK. Five independent Python groups check
exact core/base/resource hashes, existing structural schema/revision, finite
source/request/query relations, limited mutation premises and licensing/CI. The
small Python model is expressly not general admission or independent human review.
No actual events, requests, values, storage, grants, receipts or host execution are
generated. Source/native selection is deliberately unchanged in this raw increment.
