Freeze/sign dedicated `codex/named-type-critique` before critique or new probes.
Preserve Manifest, every accepted semantic/core/resource/source/schema publication,
current production behavior and quotas, and all current/historical benchmark,
corpus, guard, receipt, generator and report bytes. Source0.17/companion0.16 remains
C12/IR0.4. No type alias grammar, new nominal type, reusable work/predicate/template,
provider repin, C13 source adoption, editor/export, runtime or concurrency admission
is implemented by this scope. Benchmark adoption/archive remains separate.

Write a critique before new inactive measurement/probe code. Use ADR-0083's actual
native outer-type measurements and ADR-0084's genuine protection reduction to
identify the next independent authoring bottleneck. Distinguish exact repeated
spelling, resolved type identity, pre-existing nominal resource names and actual
user benefit; do not sum overlapping expression/type metrics or call upper bounds
measured savings. Inspect real full RP-01/RP-03 type families and RP-08 intent/gaps.
RP-08 has no full lowerable source; never fabricate that evidence.

Compare explicit local transparent type names with existing pinned nominal
resource types, layout-only changes, parameterized/domain libraries and deferring
types until hygienic service/predicate reuse. Compare readable definition/use
spellings under the plain-English goal; label every new syntax example paper-only.
Do not settle a production grammar here. Preserve exact nested nominal pins,
structural shapes, choice/outcome tags, integer/decimal/optional/list meanings,
lexical references, alias identity, privacy and type-checking/error behavior.

work occurrences into one. Include unused invalid definitions, forward references,
cycles, shadowing/kinds/qualifiers, rename/reorder/copy/tombstones and exact resource
visibility in future positive/negative criteria.

Specify cumulative pre-allocation expansion accounting for any eventual alias DAG:
validate all definitions/cycles, charge definitions and repeated uses, cap depth,
nodes/work/bytes including caches, and refuse exponential expansion without partial
output. Existing 1MiB/depth64/parser1M/lowering100k/semantic shared bounds remain.
Discuss how the existing exact source-version feature matrix and managed companion
would be maintained without silently widening old versions. No source substitution
or production Python compiler. Immutable expanded type descriptions are not live
values or authorization.

If new probes are needed, freeze the critique first and use existing Rust parsing /
strict resolved IR as evidence, with bounded IO/work/output and no benchmark writes.
A pure paper option comparison may use the existing reproducible measurements;
do not add utility code solely to repeat established facts. Any semantic-equivalence
claim requires actual lowering/checking. Actual users, independent review and
browser/host execution cannot be simulated or generated.

personal owner review. Production grammar/profile/schema and implementation would
need their own subsequent signed scope. Keep complete near-English/managed
