# Reversible authoring package and managed changes: frozen contract scope

**Date:** 2026-11-14<br>

**Authority:** ADR-0018 / ADR-0093 direction; dedicated contract-only deliverable

Freeze/sign `codex/reversible-authoring-contract` before contract publication.
Compare complete alternatives for preserving authoring-only structure: a separate
authoring package, versioned IR annotations, or IR-only canonical text export.
Assess the Manifest's one meaning/two forms, metadata privacy, human instructions
in semantic body, progressive disclosure and exact0.x admission. Explain the
choice in ADR-0094 under owner delegation, not personal owner or independent review.

Publish exact versioned normative artifact(s), closed schema(s) and worked
positive/negative packages/change requests with raw-byte pins before any later
production implementation. Select an explicit supported component/profile matrix;
preserve source19/companion18/C12 and every older accepted grammar/schema/contract
byte. Do not add source20, IR calls, generic work templates, nominal membership,
new host/runtime authority or relaxed component quotas in this scope.

Define semantic revision separately from authoring/package/layout integrity.
Source-only definitions, names, managed identities, resource pins, original source
and strict companion cannot be reconstructed uniquely from execution IR. Specify
how both forms retain that information without conflicting sources of truth or
unchecked metadata that hides actual semantics. Every claimed semantic projection
must agree with real native lowering and exact resource bytes; inconsistent or
unknown state refuses rather than silently falling back. Invalid working drafts
must not masquerade as validated models or emit a successful candidate/export.

Define managed operation boundaries and preconditions, including identity-stable
rename, explicit new-identity copy, retirement/tombstones, layout-only changes and
import/export/roundtrip responsibilities. Do not recover IDs from names/positions,
merge occurrences/storage/authority, or reinterpret opaque literal/type payloads.
Handle source-only versus semantic symbols, qualified references, lexical privacy,
wire aliases, annotations, conflict/stale-base detection and deterministic output.
Distinguish a complete contract from a later bounded implementation slice; unsupported
operations/constructs require explicit refusal, not lossy visual placeholders.

Specify faithful visual/source representation and versioned non-semantic layout
references for accepted constructs, including source-only tests and type/protection
names. Establish accessible inspect/edit/export obligations and how protected
content, audience views and authoring permissions are represented and checked.
Authoring access is not live process authorization: reports/digests/layout/claims
must not grant host permission or invent provider truth/current authority. Do not
claim production security, actual users, browser execution or independent review
from synthetic fixtures. Keep ordinary user flows free of wire/JSON bookkeeping.

Bound whole transport and components explicitly, including bytes/items/depth/work/
output and cumulative expansion/proof metadata, without increasing existing compiler/
SDK quotas. Require private diagnostics, actionable source/entity locations, exact
unknown-version/dialect handling and no partial-success output. Reuse existing native
judgments for actual semantics; a Python/schema contract oracle is not native
managed-edit implementation, full validation or execution evidence.

Exercise meaningful contract vectors for equivalent semantics/different authoring,
layout-only stability, wrong semantic/source/resource pins, stale bases, malformed
or unsupported fields/operations, identity collisions/retirement, private references,
literal opacity and cumulative limits. Preserve all965 benchmark files, current/
historical/experimental captures and every accepted publication. RP-01/03 current
views and RP-03's legitimate external-region refusal stay unchanged.

Run relevant publication/schema/documentation/native controls and required final-head
native/Wasm/Python CI. Review complete diff separately; audit all unresolved review/
inline/conversation/CodeRabbit bodies, fix valid findings and explain rejected ones.
Skipped bot is no review evidence. Expected-head signed merge and progress/parent
update follow successful CI/fresh audit. Later native managed operations/paired
prototype require separate signed implementation scopes after this contract.

Full RP-08 design/coverage/package, complete diagnostics/validator/conformance,
cross-form cycles and actual representative-user evidence remain explicit Phase1
dependencies, not deferred to the Phase3 production studio. All40 scenarios Partial,
G1–G4 conditional and parent46 draft. No Phase2/new phase chat; stop only at the
