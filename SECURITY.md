# Security policy

## Supported versions

Choreoform has not published a software release and makes no production
security-support promise yet.

| Version | Supported |
| --- | --- |
| No released versions | No |
| Current `main` branch | Reports welcome; no stability guarantee |

This table will be replaced with an explicit release-support matrix before the
first public software release.

## Reporting a vulnerability

Do not disclose a suspected vulnerability in a public issue, pull request,
discussion, or social-media post.

Use [GitHub private vulnerability reporting](https://github.com/cyborg-nomade/choreoform/security/advisories/new).
If you cannot access that form, email
[uriel.fiori@gmail.com](mailto:uriel.fiori@gmail.com) with the subject
`Choreoform security report`.

Include, where possible:

- the affected component, commit, or version;
- the vulnerability's impact and required conditions;
- reproduction steps or a minimal proof of concept;
- known mitigations or workarounds;
- whether the issue is already public or subject to a disclosure deadline; and
- how you would like to be credited.

Do not include secrets, personal data, or destructive production evidence that
is not necessary to investigate the report.

## What to expect

The maintainer will aim to acknowledge a report within seven calendar days.
After triage, the maintainer will privately communicate whether the report is
accepted, what additional information is needed, and the expected next update.
Response and remediation times depend on severity and project maturity; an
acknowledgement is not a promise of a fix by a particular date.

Accepted vulnerabilities will be handled through coordinated disclosure. The
project will work with the reporter on a disclosure date, prepare and verify a
fix where feasible, credit participants who consent, and publish a GitHub
security advisory when users need to take action. The project may request a
CVE for eligible released software.

Please act in good faith, avoid privacy violations and unnecessary disruption,
and give the project a reasonable opportunity to investigate before public
disclosure. This policy does not create a bug-bounty program or authorize
testing against systems or data you do not own or have permission to test.

## Non-security reports

Questions, feature requests, and ordinary defects belong in the public issue
tracker. Code of Conduct concerns use the separate private channel in
[CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
